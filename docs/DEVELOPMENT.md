# 開発メモ（DEVELOPMENT）

## 構成

- 配布物は **単一HTML**（`jsox_flow_builder.html`）。SheetJS（値のみExcel）と ExcelJS（装飾Excel）を同梱
- ソースも現状は単一HTML内にセクションコメントで区分（データモデル／フロー描画／グリッド／取込／出力／評価／AI連携／保全 等）
- 将来案：開発時のモジュール分割＋ビルドで単一HTML化（大規模リファクタは段階的に行う方針）

## データモデル（正本）

- `db` … プロジェクト全体（projectName / mode / features / processes[] / library / mappingProfiles / customCols）
- `P()` … アクティブプロセス（steps[] / rcm[] / journals[] / deficiencies[] / evidence{} / prior / revisions）
- `outProc()` …［成果物へ反映］時点のスナップショット。成果物はここから描画
- `applyAll()` … P() → 反映スナップショットへコピー
- 後方互換：読込時 `normalize()` が新フィールドを補完（既存 .json はそのまま開ける）

## エラーの扱いと診断情報

例外は握りつぶさず、**何が失敗し・データはどうなり・次に何をすべきか**を日本語で提示します。

- `appError({title,message,detail,recover})` … 利用者向けの説明と開発者向けの詳細（折りたたみ）を分けて表示。
  `recover:true` で［保存(.json)で保全］［自動保存から復元］［再読込］の復旧ボタンを出す
- `window.addEventListener("error"/"unhandledrejection")` … 予期しない例外を捕捉。
  **ボタンが無反応のまま放置されない**ようにするための最後の受け皿。同一メッセージは1回だけ提示する
- `diagInfo()` / `copyDiag()` … 不具合報告用の環境情報（アプリ版・スキーマ版・モード・画面・データ規模・
  自動保存状態・UA・画面サイズ・直近のエラー）。**業務データの中身は含めない**。ファイルメニューから取得可能
- 処理が部分的に失敗した場合は「成功」で終わらせない
  （例: 装飾Excelは出力できたが詳細シート／フロー図画像を作れなかった場合は、その旨をトーストで通知）

新しく `try/catch` を書くときは、握りつぶす場合でも「利用者が気づかなくて困るか」を判断してください。
困るなら `toast()` か `appError()` で伝え、困らない場合（任意設定の保存失敗など）はコメントで理由を残します。

## 出力と画面データの照合

出力が画面の内容とずれていないことを、セルフテスト「出力と画面データの照合」で機械的に確認しています。

- **全データExcel** … 組み立てを `buildDataWorkbook()` に分離してあり、ダウンロードせずに中身を検査できます。
  業務記述書の行数＝工程数、各行の工程No・業務内容、**工程に紐づく統制IDの並び**、RCMの行数・統制ID・対象工程No、
  仕訳の行数、Coverageの行数＝勘定科目数を照合します
- **draw.io** … ノード数＝有効工程数、レーン数＝部門数、XMLとして妥当であること
- **Mermaid** … ノード数＝有効工程数
- **フロー図SVG** … 全工程のラベル・使用システム・紐づく統制タグが図に含まれること

画面別Excel（`exportDocXlsx`）はDOMの表から生成するため、画面との一致は構造上保たれます。

出力形式を変更したときは、この照合テストの期待値も合わせて更新してください。
新しい出力を追加する場合は、**件数・ID・紐づけ**の3点を最低限テストに入れてください。

## 自動保存と保存容量

自動保存は `localStorage`（ブラウザ全体で概ね5MB）に2世代（`AS_KEY` / `AS_PREV`）保持します。
容量に対する挙動は **状態 `_asState`** で管理し、状態が変わったときに必ず利用者へ通知します。

| 状態 | 意味 | 画面表示 |
|---|---|---|
| `ok` | 全内容を保存できている | 「自動保存: 8/2 14:32 ・ 使用 1.2MB ／ 添付 0.5MB」 |
| `partial` | 容量超過のため**添付の実体を除いて**保存（`_stripHeavy`） | 「（添付を除く）」＋赤字、復元ダイアログにも明示 |
| `off` | 保存自体が失敗し停止 | 「自動保存: 停止中 — ［保存(.json)］で保全してください」＋赤字 |

- 添付の合計が `ATT_BROWSER_SAFE`（3MB）を超える見込みになった時点で、**添付の追加時に**その旨を案内します
- `ATT_MAX_TOTAL`（25MB）は `.json` 保存を前提とした上限です。localStorage には収まらないため、
  この規模では自動保存が `partial` になるのが正常な動作です（文字情報は保護されます）
- **失敗を黙って握りつぶさないこと**。`catch` で `_asDisabled` を立てる場合は必ず `setAsState("off")` を呼びます

### 実測（Chrome・2026-08-02）

| 規模 | JSON | 描画（最大） | 保存 | 読込 | 自動保存 |
|---|---|---|---|---|---|
| 工程100 / RCM60 | 0.1MB | 33ms | 0ms | 4ms | 3ms |
| 工程500 / RCM300 | 0.4MB | 120ms | 1ms | 9ms | 13ms |
| 工程1000×5プロセス / RCM600 | 3.8MB | 203ms | 12ms | 35ms | 98ms |

添付を積み上げた場合、実測では 3MB までは `ok`、5MB 以降で `partial` へ遷移することを確認しています。

## 画面へ値を出すときのエスケープ

取込データ（Excel/CSV/JSON）・AI回答・貼り付け文字列は**すべて信頼できない入力**として扱います。
HTMLを組み立てて `innerHTML` に渡す箇所では、値の埋め込み先ごとに関数を使い分けてください。

| 埋め込み先 | 使う関数 | 理由 |
|---|---|---|
| テキスト（要素の中身） | `esc()` | `& < >` をエスケープ |
| 属性値（`title="…"` 等） | `escAttr()` | 上記＋ `"` |
| **インラインイベント内のJS文字列**（`onclick="fn('…')"`） | **`escJs()`** | 属性値は**HTMLデコード後にJSとして解釈**されるため、HTMLエスケープだけでは `'` による脱出を防げない |
| 画像の `src` | `safeImgSrc()` | `data:image/…;base64,` のみ許可（外部URL・`javascript:`・属性脱出を遮断）。許可外は空文字を返すので `<img>` 自体を出さない判定に使う |
| draw.io などのXML出力 | `xesc()` | XML属性用 |

`escJs()` が必要な理由はセルフテスト「エスケープとXSS対策」で実証しています
（同じ経路に `escAttr()` だけを使うとコードが実行されることをテスト内で確認しています）。
新しく `onclick="fn('${…}')"` の形を書く場合は必ず `escJs()` を通してください。

## 添付ファイルの取り扱い（工程証跡 / 証憑 / 規程・資料）

`blob:` URL は生成元と**同一オリジン**として扱われます。任意のHTML・SVGを新規タブで開くと、
その中のスクリプトが本アプリの権限で実行され、`localStorage`（自動保存データ）や
IndexedDB（フォルダハンドル）へアクセスできてしまいます。このため次の方針をとっています。

- **受け入れ形式は allowlist**（`ATT_TYPES`）。HTML・SVG・スクリプト・実行ファイルは追加できません
- **上限**: 1ファイル `ATT_MAX_FILE`（ブラウザ内5MB / フォルダ格納50MB）、1か所 `ATT_MAX_COUNT`（20件）、
  プロジェクト全体のブラウザ内保存 `ATT_MAX_TOTAL`（25MB）
- **開き方は `attView()` に集約**。画像のみ `<img>` でプレビュー（スクリプトは実行されない）、
  それ以外は必ずダウンロード保存とし、**blob を新規タブで開かない**
- 過去に追加された allowlist 外の添付も、開く時点でダウンロード扱いになります
- ファイル名は `attSafeName()` でパス区切り・制御文字・先頭ドットを除去して保存します

形式を追加する場合は `ATT_TYPES` に追記し、**画面内で開いてよいのは画像だけ**という原則を崩さないでください。

## データ形式（スキーマ）とバージョン

- プロジェクトJSONは `schemaVersion`（整数）を持ちます。現行は **1**（アプリ内定数 `SCHEMA_VERSION`）。
- `schemaVersion` が無いファイルは **v0（版番号導入前の旧データ）** として扱い、移行してから読み込みます。
- 読み込みは `loadProjectData()` が唯一の入口です。**検証 → 移行 → 適用** の順で処理し、
  途中で失敗した場合は `db` と `_applied` を元に戻すため、**部分的に壊れた状態が残りません**。
  - `validateProject(o)` … 形式・必須配列・ID重複を検査（errors / warnings を返す）
  - `migrateProject(d)` … `SCHEMA_MIGRATIONS` を版番号順に適用。アプリより新しい版は読み込み前に警告
- 保存時は `schemaVersion`（読み込んだ版が新しければその値を維持）と `appVersion` を記録します。

### 形式を変更するときの手順

1. `SCHEMA_VERSION` を +1 する
2. `SCHEMA_MIGRATIONS` に新しい版番号のキーで移行関数を追加する（旧構造 → 新構造の変換のみ。項目の欠損補完は `normalize()` の役割）
3. 旧形式のサンプルJSONで読み込みを確認し、セルフテスト「スキーマ移行（旧形式→現行）」を更新する
4. 後方互換を壊す場合は CHANGELOG に移行方法を明記する

## ソース分割の段階的移行計画（配布物は単一HTMLを維持）

### 現在のセクション境界（単一HTML内・コメントで区分済み）

`<style>`（デザイントークン/コンポーネント/印刷） → `<body>`（ナビ/各page/モーダル/オーバーレイ） → SheetJS → ExcelJS → メインスクリプト（データモデル → ユーティリティ → フロー描画 → グリッド → ギャップ → 出力(Excel/CSV/drawio/mermaid) → モード設定 → テンプレート → 取込 → 反映モデル → 成果物描画 → 評価(evalwork/oewp) → 証憑/フォルダ格納 → 棚卸 → ヘルプ → AI連携 → データ保全 → ガイド/スタート → セルフテスト → 起動）

### 主なグローバル依存

- 状態: `db` / `curPage` / `_applied` / `_viewPref` / `_tour` / `_aiCands` / `_imp` / `fscale`
- 中核関数: `P()` `outProc()` `applyAll()` `normalize()` `show()` `esc()` `toast()`
- DOM ID結合が強い層: グリッド描画（stepBody等）・モーダル群

### 分割候補（リスク低い順）

1. 定数（STEP_TYPES / PHASE_COLORS / ASRT_* / SAMPLE_GUIDE / HELP_CAT_META）
2. サンプルデータ・テンプレート（exampleDB / TEMPLATES）
3. ユーティリティ（esc / download / dataUrlToBlob / idNum / rcmSorted / toast）
4. セルフテスト（runSelfTest — 純粋に付加的で最初の切り出しに最適）
5. ヘルプ記事データ（HELP配列）
6. AI連携（プロンプト生成・取込パース）
7. 出力層（drawio/mermaid/ExcelJS変換）
8. 最後: データモデル・描画中核（十分なテスト整備後）

### ビルド設計（案）

```
src/
  00_style.css  10_body.html  20_vendor/(sheetjs,exceljs)
  30_model.js ... 90_boot.js  tests/selftest.js
build.js   # マーカー置換で dist/jsox_flow_builder.html に連結
dist/jsox_flow_builder.html   # 従来どおり単体配布
```

- `build.js` は Node 標準のみで実装（依存ゼロ）。CI で「ビルド結果 = リポジトリのHTML」を検証し乖離を防ぐ
- 移行単位ごとに: 切り出し → ビルド → セルフテスト26項目 → コミット、の小さなサイクルで進める
- 一度に全面リファクタリングしない。各段階で既存JSON・自動保存の互換を維持

## Release用配布HTMLの作成手順

リポジトリ構成は変えず、Release作成時にローカルでコピーして添付する運用とします（開発元と配布物の乖離防止のため、必ずタグを打ったコミットからコピーする）。

```bash
git checkout v0.9.0-beta
cp jsox_flow_builder.html jsox_flow_builder-v0.9.0-beta.html
gh release upload v0.9.0-beta jsox_flow_builder-v0.9.0-beta.html assets/samples/sample_project.json
```

- 配布ファイル名はタグと一致させる（`jsox_flow_builder-vX.Y.Z(-beta).html`）
- 添付は「単体で使い始められる」最小セット: 配布HTML＋サンプルJSON（必要に応じてサンプルExcel）
- アップロード後、ダウンロードして `?selftest=1` が18/18で通ることを確認する
