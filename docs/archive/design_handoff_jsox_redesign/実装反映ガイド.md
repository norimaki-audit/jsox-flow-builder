# 実装反映ガイド — リデザインを `jsox_flow_builder.html` へ適用

対象モック: `J-SOX 三点セット リデザイン.dc.html`
適用先: `jsox_flow_builder.html`（バニラJS SPA／SheetJSインライン同梱・単一HTML）

> 設計思想は維持：構造化データ(`db`)が正本／入力は `P()`・成果物は `outProc()`／ローカル完結。
> UIの見た目とIA（情報設計）だけを差し替え、データモデル・反映モデル・入出力ロジックは触らない。

変更後は HANDOFF.md「検証方法」（`node --check` ＋ 整合チェック ＋ jsdomスモーク）を必ず通すこと。

---

## 0. 進め方（推奨順）
1. **デザイントークン**を `<head><style>` 先頭に追加（§1）
2. **アプリバー + 左ナビ**を差し替え（§2）— `show()` ルーターはそのまま流用
3. **業務記述書グリッド**の見た目更新（§3）
4. **フロー図**の記号を標準化（§4）
5. **RCM / ダッシュボード / 評価・点検**の体裁（§5〜6）
6. **マニュアルモード**の表示制御を拡張（§7）
7. **詳細パネル・テンプレート選択モーダル**を追加（§8〜9）

各ステップは独立して適用・検証できる。まず§1+§2だけ入れて全体の見た目を変え、以降は段階的に。

## 2. アプリバー + 左ナビ（IA刷新）

### 2-1. 「編集」と「成果物」の重複を解消
現状は左メニューに「編集（入力）」と「成果物（反映で更新）」が別項目で並ぶ。これを **帳票ごとに1項目**へ統合し、各画面内に **編集 / プレビュー** トグルを置く。

- ルーター `show(pg)` はそのまま使う。`pg` を `steps` / `flow` / `rcm` の3つに集約。
- 画面内トグルの状態 `viewMode('edit'|'preview')` を追加。
  - `edit` → 既存の編集グリッド（`P()` 由来、`inp/sel/onGrid`）
  - `preview` → 既存の成果物描画（`outProc()` 由来、`renderStepsDoc`/`renderRcmDoc`）
- つまり **同じ関数を呼び分けるだけ**。`P()`/`outProc()`/`applyAll()` のロジックは不変。

### 2-2. ナビ構成（J-SOXモード）
```
メイン        : ダッシュボード
三点セット作成 : 業務記述書 / フロー図 / RCM        ← 各画面に編集|プレビュー
評価・点検     : 評価結果 / ギャップチェック / ロールフォワード / 不備管理 / 証憑
データ        : 取込 / 規程・資料
（下部固定）   : 使い方・基準参照
```
- **ナビのスクロール不具合の修正**: `nav.side{position:sticky;top:0;height:100vh;overflow-y:auto}` ＋ 中央リストを `flex:1;overflow-y:auto`、ヘルプを `flex:none` で最下部固定。これで「ヘルプまで届かない」問題が解消（HANDOFFの sticky 修正と整合）。

### 2-3. アプリバー
左: ロゴ(IC Studio) → モード切替（J-SOX / 業務マニュアル）→ プロセス選択ピル → 「プロセス追加」。
右: 反映ステータス（未反映 N件／反映済み）→ 反映ボタン → 保存 / Excel出力。
- 固定要素はすべて `flex:none;white-space:nowrap`、プロセス名のみ `min-width:0;overflow:hidden;text-overflow:ellipsis`（狭幅で名前だけ省略、他は崩れない）。

## 3. 業務記述書グリッド（可読性）

`renderStepsDoc` / 編集グリッド生成箇所に適用：

- **業務(`gyomu`)ごとにグルーピング**。グループ見出し行（フェーズ色ドット＋名称＋件数）→ その下に工程行。行に3pxの左フェーズ帯。
- **行区切りは点線**（`border-bottom:1px dashed var(--c-border)`）。
- **種類(`type`)はバッジ**（開始/終了/手動処理/システム処理/判断/書類で色・アイコン分け）。
- **担当部門はカラーチップ**（部署ごとに色ドット＋淡色背景）。
- ヘッダーは sticky。セル間に薄い縦罫線。
- 各行に **📝 詳細ボタン**（§8）。詳細ありは塗り／なしは枠線で区別。
- 単位ラベルはモードで「工程／手順」を切替。

データは既存 `step` をそのまま使用（`no/gyomu/dept/role/type/label/detail/system/evidence`）。`detail` は §8 のパネルへ。

## 4. フロー図 — JIS標準記号

`renderNode` / `renderEdge`（および出力 `dioStyle`/`mmShape`/`buildDrawioXml`/`buildMermaid`）：

| 種類 | 記号 | 実装 |
|---|---|---|
| 端子(開始/終了) | 角丸(ロゼンジ) | `border-radius` 大 |
| 処理 | 長方形 | 角丸2–4px |
| 手作業 | 台形 | `clip-path:polygon(0 0,100% 0,87% 100%,13% 100%)` |
| 判断 | ひし形 | `clip-path:polygon(50% 1%,99% 50%,50% 99%,1% 50%)` |
| **書類** | **下辺が一本の波線** | `clip-path:path('M 0 0 L W 0 L W 42 C .. 50 .. 50 .. 42 C .. 34 .. 34 0 42 Z')`（ノードは固定px） |
| データベース | シリンダ | `border-radius:50% / 13px` ＋ DBアイコン |

- **判断は必ず Yes/No の2分岐**：右頂点＝「はい・限度内」、下頂点＝「いいえ・超過」をラベル付きで描画。
- **R/C表示**：統制が紐づく工程の右上に `R0xx`(赤) / `C0xx`(teal) のミニタグを重ねる（`s.system`/`step_no` から該当判定）。
- **フェーズ区切り**：スイムレーン横方向に薄い破線をフェーズ境界へ。フェーズ帯（受注/承認/出荷/売上計上）は左の縦書きラベル帯＋**キャンバス全幅の淡色帯（opacity .42）**で行う。
- マニュアルモードでは R/C タグ・凡例を非表示（既存 FIXES12-A1 と整合）。

### 4-2. フロー図ツールバー（カード内上部・プロトタイプ実装済み）
フロー図カードの最上段に1行のツールバーを置く：
- 左：**コンパクト凡例**（端子・処理・手作業・判断・書類・DB・R/C。ラベルは短く、`white-space:nowrap`）
- 右：**システムレーン トグル**（OFFでシステムレーン列・DBノード・破線コネクタを非表示、レーン数4に）／**ズーム**（− / % / ＋、レベル 50–150%、%クリックで100%へ。実装は `zoom` CSSプロパティで可）／**書き出し**（draw.io / Mermaid / PNG — 既存 `buildDrawioXml`/`buildMermaid` に接続）
- レーンヘッダは `position:sticky;top:0` で縦スクロール時も固定。
- キャンバス背景は**ドット方眼**（`radial-gradient(#DEE7E3 1px,transparent 1px)` / 22px間隔）。
- エッジは直交配線＋**角丸コーナー**（r≈9）。
- **ノードクリックで詳細パネル（§8）を開く**。ノードに `cursor:pointer`＋ホバーで僅かに浮く。

## 6. ダッシュボード / 評価・点検

`renderDash` ほか各 `renderX`：
- **ダッシュボード**: KPIカード（統制数/キー統制/評価進捗/網羅率/不備/証憑）＋ 整備運用評価の積み上げバー ＋ 勘定科目×アサーション網羅マトリクス（未カバー=赤セル, 既存 `coverage()`/`covAddRcm`）＋ 不備3段階 ＋ 証憑格納状況。
- **評価結果**: 統制別に 整備評価/運用評価/サンプル/例外/評価者/評価日/総合 のテーブル。
- **ギャップチェック**: 要対応/警告/提案 の集計カード ＋ 指摘リスト（`add(lv,cat,msg,pg)` の `pg` で該当画面へ遷移、既存 FIXES15）。
- **不備管理**: 3段階サマリー ＋ 明細テーブル（区分/統制/内容/原因/金額/期限/状況/再評価）。
- **証憑**: 統制ごとカード（依頼先/期限/状況＋ファイルチップ、未格納は空状態）。

## 12. よくある適用ミスと修正（初回適用レビュー）

初回の適用で頻出する崩れと直し方。**プロトタイプ `J-SOX 三点セット リデザイン.dc.html` が正**。差異があればプロトタイプに寄せる。

### 12-A【最重要】左ナビの「編集／成果物」二重が残る
- 症状: `三点セット作成`（プロセス / 業務記述書 編集 / RCM 編集 / フロー図 / 仕訳 編集）と `成果物`（業務記述書 / RCM）が**別項目で併存**している。
- これは §2-1 の統合が未適用の状態。**入力ページと出力ページを別ナビにしない**こと。
- あるべき姿:
  ```
  メイン        : ダッシュボード
  三点セット作成 : 業務記述書 / フロー図 / RCM        ← この3つだけ
  評価・点検     : 評価結果 / ギャップチェック / ロールフォワード / 不備管理 / 証憑
  データ        : 取込 / 規程・資料
  （下部固定）   : 使い方・基準参照
  ```
- 実装: 「業務記述書 編集」と「業務記述書（成果物）」を **1つの `業務記述書` ナビに統合**し、画面右上に **編集｜プレビュー トグル**（`viewMode`）。`edit`→既存 `P()` グリッド、`preview`→既存 `outProc()` 描画を**呼び分けるだけ**。RCM も同様。「仕訳 編集」が独立機能なら `データ` か別グループに移すか、対象外なら出さない。
- 旧 `show()` の page id（例 `stepsEdit`/`stepsDoc`）が分かれている場合は、ナビからは `steps` の1エントリだけ出し、`viewMode` で内部 id を出し分ける。

### 12-B 画面の上下に濃い緑の帯が出る
- 症状: ページ最上部・最下部に `--c-primary`(#0E7C73) のダークグリーン帯。
- 原因: `body` か最外ラッパの `background` に primary を当てている／ヘッダーやフッターの高さ計算で primary 背景がはみ出している。
- 修正: **アプリ背景は `--c-bg`(#F4F6F6)**。`body{background:var(--c-bg)}`。primary はボタン・アクティブナビ・アクセントのみ。アプリバーは `background:var(--c-surface)` ＋ 下罫線 `1px solid var(--c-border)`（濃緑バーにしない）。`html,body{margin:0}` も確認。

### 12-C テーブルが画面右へはみ出す / 横に伸びきる
- 症状: 業務記述書グリッドの右端（使用システム・証跡・Yes先・No先…）が画面外まで伸び、ページ全体に横スクロールが出る。
- 原因: グリッドを**カードで内包しておらず**、`overflow` 制御がない。
- 修正:
  - メイン領域: `main{flex:1;min-width:0;overflow:auto;padding:24px}`（`min-width:0` が無いとflex子が縮まずはみ出す）。
  - グリッドは**白カードで内包**し、横はカード内スクロール:
    ```css
    .grid-card{background:var(--c-surface);border:1px solid var(--c-border);border-radius:var(--r-card);overflow:auto;}
    .grid-card table{min-width:1080px;width:100%;} /* 列が多い時だけカード内で横スクロール */
    ```
  - 列幅は固定px＋`業務内容`だけ可変（`minmax(240px,1fr)`）。ページ自体に横スクロールを出さない。

### 12-D プロセス選択ピルが「販売プロセス（受…」で切れる
- 許容範囲だが、気になる場合はピルの `max-width` を広げる／`title` 属性でフル名をツールチップ表示。固定要素（モード切替・ボタン群）は `flex:none;white-space:nowrap`、**プロセス名のみ** `min-width:0;overflow:hidden;text-overflow:ellipsis`。

### 12-E ナビが最後（ヘルプ）まで届かない（既知の課題）
- `nav.side{display:flex;flex-direction:column;height:100vh}` ＋ リンク群 `flex:1;overflow-y:auto` ＋ ヘルプ `flex:none`。`position:sticky;top:0` も付与。

> 修正後は §11 の検証（check.py / node --check / smoke.js / 目視）を再実行。
